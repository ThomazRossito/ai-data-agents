# Knowledge Base — Migração SQL Server → Databricks

> Fonte de verdade operacional do agente **sqlserver-to-databricks**. Diferente de `ssis-migration/` e
> `ssas-migration/` (que têm `concepts/` próprios), este domínio **agrega** concepts que já vivem em
> outras KBs — porque cobrem terreno compartilhado com `migration-expert`, `databricks-engineer` e
> `governance-auditor`. Consultar SEMPRE antes de migrar um banco SQL Server. NÃO inventar mapeamentos.

## 1. Escopo

Migração de um **banco/instância SQL Server inteiro** (schema físico, dados, objetos T-SQL, CDC,
reconciliação, cutover) para **Databricks**. Diferente de:

- pacotes **SSIS** (`.dtsx`) → `kb/ssis-migration/` (agente `ssis-to-databricks`)
- modelo tabular **SSAS** (`.bim`/`.vpax`) → `kb/ssas-migration/` (agente `ssas-to-databricks`)
- migração genérica cross-platform (SQL Server OU PostgreSQL → Databricks OU Fabric, fluxo mais raso) →
  `kb/migration/` (agente `migration-expert`)

Este agente é a especialização mais profunda do trio SQL-Server-específico: só SQL Server como origem,
só Databricks como destino, seguindo a metodologia completa do curso oficial Databricks *"SQL Server
Migration"* (Discover→Design→Execute→Activate→Enable→Closeout).

## 2. Fluxo de conversão (8 fases + gate)

```
DISCOVER → ASSESS → DESIGN → [GATE: SPEC + aprovação humana] → CONVERT → INGEST → CDC → VALIDATE → CUTOVER
```

Mapeamento à metodologia oficial do curso: DISCOVER/ASSESS/DESIGN ≈ *Discover*+*Design*; CONVERT ≈
*Execute*; INGEST/CDC/VALIDATE/CUTOVER ≈ *Activate*; observabilidade/governança contínua pós-cutover ≈
*Enable*/*Closeout* (fora do escopo direto deste agente — ver escalações em §6).

> **Gate obrigatório:** entre DESIGN e CONVERT o agente entrega um documento de proposta (**SPEC**) e
> **PARA para aprovação humana** (Step 0.6A / Constituição §2.2). Nenhum DDL/código é gerado antes do
> aceite — reforçado por um hook de enforcement (`enforce_migration_gate`) que bloqueia uma 2ª
> delegação de migração no mesmo turno.

## 4. Mapa de Tipos — Resumo (fonte de verdade: o gerador)

O mapa determinístico completo vive em `scripts/sqlserver_generate.py` (dict `_SIMPLE`) — **nunca
reimplementar à mão**. Casos que exigem atenção (detalhe em `tsql-conversion-catalog.md` §1):

| SQL Server | Databricks | Cuidado |
|---|---|---|
| `TINYINT` | `SMALLINT` (**não** `TINYINT`) | SQL Server é *unsigned* 0-255; Databricks `TINYINT` é *signed* -128..127 — trunca valores >127 |
| `MONEY` / `SMALLMONEY` | `DECIMAL(19,4)` / `DECIMAL(10,4)` | Nunca `FLOAT`/`DOUBLE` — perde centavos (anti-padrão M01) |
| `UNIQUEIDENTIFIER` | `STRING` | GUID como string(36); novos valores via `uuid()` |
| `DATETIMEOFFSET` | `STRING` ou `TIMESTAMP` + coluna de offset | Sem tipo tz-aware nativo |
| `GEOGRAPHY` / `GEOMETRY` | `STRING` (WKT/GeoJSON) | Funções **H3** do Databricks para operações espaciais |
| `ROWVERSION` / `TIMESTAMP` (nome legado) | Dropar ou `BIGINT` | **NÃO é data** — contador de versão de linha |
| `HIERARCHYID` | `STRING` | Reimplementar travessia de hierarquia com CTE recursiva |
| `XML` | `STRING` | Parse via XPath / funções JSON |
| `IDENTITY` | `GENERATED BY DEFAULT AS IDENTITY` (carga inicial) → `GENERATED ALWAYS` (pós-carga) | Documentar a troca |
| `PRIMARY KEY` / `FOREIGN KEY` / `UNIQUE` | Informational + `RELY` | Não enforced no Delta — usar Lakeflow Declarative Pipelines expectations para validação real |

## 5. Os 8 Anti-Padrões de Migração (guardrails obrigatórios)

**Skipping Assessment** · **Big-Bang Migration** · **Premature Decommission** · **Lift-and-Shift
Mentality** · **No Parallel Validation** · **Ignoring T-SQL Dialect Gaps** · **Ignoring Change
Management** · **Underestimating Governance**. Detalhe (risco + como evitar) em
`kb/migration/concepts/discovery-assessment.md` §7.

## 6. Regras do agente (resumo)

- **Grounding:** todo mapeamento vem das KBs listadas em §3. Construto T-SQL sem equivalente claro
  (dynamic SQL, CLR, linked servers, temp tables, `@@IDENTITY`, `OUTPUT`, `TRY...CATCH`, `WAITFOR`,
  full-text search, `XACT_ABORT`) → **⚠️ revisão manual**, nunca inventar equivalência.
- **Gate obrigatório:** SPEC + aprovação humana entre DESIGN e CONVERT (§2) — fronteira de turno.
- **Geradores determinísticos:** `scripts/sqlserver_generate.py` (DDL + flags + spec de reconciliação) e
  `scripts/reconcile_generate.py` (SQL de reconciliação) — nunca escritos à mão, nunca reimplementados.
- **Reconciliação em 2 fases:** snapshot histórico aprovado ANTES de ligar o CDC; depois só o delta.
  Nunca rodar as duas juntas (mascara a causa raiz do mismatch).
- **Cutover:** runbook completo (freeze window + matriz de rollback + hypercare + sign-off), nunca só
  um checklist — e nunca decommission prematuro do SQL Server.
- **Escopo:** banco relacional completo. Pacotes SSIS → `ssis-to-databricks`; modelo tabular SSAS →
  `ssas-to-databricks`; destino Fabric ou origem PostgreSQL → `migration-expert`; implementação pesada
  de pipeline → `databricks-engineer`; PII/ABAC em escala → `governance-auditor`; validação estatística
  avançada → `data-quality-steward`.
- **Idioma:** seguir o usuário (PT-BR/EN); nomes de construtos/produtos em inglês.
